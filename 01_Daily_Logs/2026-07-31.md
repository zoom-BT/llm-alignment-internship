### Deep-Dive Recap: A Real Negative Result, and a Detour Through Kaggle Datasets

**The headline number: perplexity got worse, not better (13.92 → 75.41).** Reported honestly rather than smoothed over — the internship agreement explicitly protects negative results as valid, as long as they're correctly obtained, documented, and analyzed (Article 9). The training loss curve from Thursday had already hinted at why: sharp drops at each epoch boundary are the signature of memorizing the fixed training set rather than learning a generalizable behavior, and the test-set perplexity confirms it directly. Most likely causes, identified for correction: a learning rate (`2e-4`) sized for LoRA rather than full fine-tuning, 3 full epochs of full-parameter updates on only 12k examples, and no `eval_strategy` configured to catch the problem while it was happening rather than only after the fact.

**Getting the checkpoint out of Kaggle turned into its own lesson in platform mechanics.** `run_benchmark()` gained a `model_path` parameter so the exact same evaluation code could run on either the base model or a fine-tuned checkpoint — same dataset, same metric, directly comparable numbers. But reaching that checkpoint required: discovering that a "Save & Run All" (commit) run tears down its kernel afterward (no live session to add cells to); that Kaggle's "New Dataset from Output" scans the *entire* `/kaggle/working` tree and refuses any filename with an `&` (which the cloned repo's Obsidian notes have); and, once individual files were downloaded and re-uploaded as a fresh Dataset, that the checkpoint really did evaluate cleanly on GPU in under a minute. Fixed at the source for next time: the training notebook now does a sparse `git checkout` (only `src/`, never the notes) and zips the final checkpoint into one file, so a future "New Dataset from Output" has nothing left to trip over.

**A local, CPU-only cross-check of the same evaluation ran for over 7 hours** before being killed once the (much faster) Kaggle GPU result was already in hand — a very concrete, lived reminder of exactly why GPU-dependent work was routed to Kaggle from day one, not a local afterthought.
