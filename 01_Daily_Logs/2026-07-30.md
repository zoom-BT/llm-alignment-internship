## Concepts Covered Today (In English)
### Supervised Fine-Tuning (SFT) & Memory Optimization
- **Supervised Fine-Tuning (SFT):** Adapting pre-trained weights on instruction-response pairs using cross-entropy loss.
- **Gradient Accumulation:** Calculating gradients over multiple small mini-batches before executing an optimizer step to simulate larger batch sizes on limited VRAM.
- **Gradient Checkpointing:** Trading computation for memory by recomputing intermediate activations during the backward pass instead of storing them.

### Deep-Dive Recap: Full Fine-Tuning, TRL's Real API, and a Multi-GPU Surprise

**`run_sft()` was written after inspecting TRL 1.9.1's actual installed API** (`inspect.signature` on `SFTConfig`/`SFTTrainer`) rather than guessing — TRL's API changes fast enough that trusting memory would have been a real risk. `SFTTrainer` accepts a `formatting_func` (raw example dict → formatted text), so it reuses `format_as_chat_messages()` from Tuesday directly instead of needing the manually-tokenized cache built then — a concrete case of a library doing, automatically, part of what was built by hand earlier in the week purely to understand the mechanism.

**Full fine-tuning, not LoRA, decided deliberately for this first run:** Qwen2.5-0.5B is small enough that updating all ~500M parameters fits comfortably on a T4; LoRA/QLoRA are Week 3 material, not required yet.

**`max_steps` added to `run_sft()`** specifically to support a cheap dry run (20 steps, ~3 minutes) before committing to the full multi-hour run — exactly the kind of "verify before trusting the expensive thing" habit this whole week has been about.

**A real, unexpected bug: Kaggle's "T4 x2" broke training with a device-mismatch `RuntimeError`.** Hugging Face's `Trainer` auto-wraps the model in `torch.nn.DataParallel` whenever more than one GPU is visible, splitting the batch across both — but the model had only been explicitly placed on `cuda:0`, so the two mechanisms fought each other. Fixed by setting `CUDA_VISIBLE_DEVICES=0` before `torch` is even imported, restricting the whole session to one GPU. A 0.5B model doesn't need two GPUs anyway, so nothing was lost.

**The full run: 2,253 steps (3 epochs), 5h 52m 34s on a single T4.** The loss curve dropped sharply at each epoch boundary (≈2.9→1.7, then ≈1.5→0.6) rather than declining smoothly — flagged at the time as a likely sign of memorization rather than generalization, later confirmed the next day by a much worse test-set perplexity (see Friday's log).
